# 01 · 核心分层框架：L1 → L2 → L3

> 本页是整个项目的认知地基。理解了这三个层级，你就能给市面上 90% 的 AI 产品快速"挂号"。

---

## 一、为什么要分层？

AI 产品名称满天飞：ChatGPT、Claude Code、Cursor、OpenRouter…… 很多人把它们都叫"AI"，但实际上它们扮演的角色完全不同：

- 有的提供"大脑"（模型）
- 有的提供"躯干与工具"（应用）
- 有的提供"调度网络"（网关）

把它们强行对比，就像拿"大脑""手""快递站"做横向比较，毫无意义。本项目用 **L1 / L2 / L3** 三层架构给每个产品一个清晰的坐标。

---

## 二、三层定义总览

| 层级 | 角色定义 | 判定标准 | 代表产品 | 核心产出 / 说明 |
| :--- | :--- | :--- | :--- | :--- |
| **L1：AI 模型** | 提供"大脑"，负责理解和生成内容 | **拥有自研模型，对外提供 API** | Agnes 系列、GLM、Qwen、DeepSeek-V4、Kimi 系列、Claude 系列、Gemini 系列 | 模型权重 + API 调用接口 |
| **L2：AI 应用软件** | 封装模型能力，提供具体功能服务 | **调用模型，供用户直接使用** | Chatbox、Claude Code、Codex、OpenCode、Trae、Kimi Work、Cursor | 桌面端 / IDE / 移动端软件 |
| **L3：AI 网关 / 聚合平台** | 统一接入多模型，做路由与成本优化 | **不自研模型，仅做聚合转发** | OpenRouter、ZenMux、CCSwitch | 统一 API 接口 + 管理控制台 |

---

## 三、层与层之间的关系链

```
L1 → L2        （应用直接调用模型）
L1 → L3 → L2   （应用通过网关调用模型）
```

- **直连模式**：L2 应用直接调用某个 L1 模型的官方 API（如 Cursor 调 Claude）。
- **网关模式**：L2 应用先请求 L3 网关，由网关决定路由到哪个 L1 模型（如通过 OpenRouter 调多家模型）。

---

## 四、判定一个产品属于哪一层？三问法

拿到任意一个 AI 产品，依次问三个问题：

1. **它有没有自研模型？**
   - 有 → 至少含 **L1**。
   - 没有 → 排除 L1，进入下一问。
2. **它是否给终端用户提供了可操作的界面 / 工具？**
   - 有 → 至少含 **L2**。
   - 没有 → 进入下一问。
3. **它是否在不自研模型的前提下，统一接入多家模型做路由？**
   - 是 → 属于 **L3**。

> 一个产品可以同时横跨多层，详见 [03 · 混合角色产品](./03-hybrid-roles.md)。

## 五、前沿案例补充

> 💡 **Agnes AI**
> 新晋全模态模型提供商，其文本模型 Agnes-2.0-Flash 在智能体评测榜单上进入 Top 10，首周 API 调用量达 3.12 万亿 Token。属于典型的 **L1 + L2 + L3 全栈型平台**。

> 💡 **ZenMux**
> "全球首个支持保险赔付机制的企业级大模型聚合平台"，创新性地引入了"API 保险赔付"机制和质量监控，属于 **L3 网关层** 的质量保障型演进。
