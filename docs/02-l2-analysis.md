# 02 · L2 应用软件深度剖析

> L2 是离用户最近的一层。同样是"AI 应用"，被动应答的聊天框和能自己干活的智能体，已经是两个物种。

---

## 一、L2 的内部分裂：L2-A vs L2-B

L2 层正经历从"被动响应"到"自主执行"的深刻变革，据此分为两类：

| 定义 | 核心特征 | 代表产品 | 核心能力 |
| :--- | :--- | :--- | :--- |
| **L2-A：传统应用软件** | 被动响应式，一问一答 | Chatbox、ChatGPT App、DeepSeek App、Kimi App、智谱清言 App | 用户给指令 → 软件响应；基础对话，无自主规划能力 |
| **L2-B：AI 智能体（Agent）** | 目标驱动式，自主规划与执行 | Claude Code、Codex、OpenClaw、Cursor、OpenCode、Trae、Kimi Work | 用户设目标 → 软件自动拆解任务、调用工具、验证结果，交付完整成果 |

**一句话区分**：L2-A 回答你的问题，L2-B 完成你的任务。

---

## 二、L2-B 智能体的三大核心能力

| 能力 | 说明 |
| :--- | :--- |
| **自主规划（Planning）** | 根据目标自动分解为多步骤任务 |
| **工具调用（Tool Use）** | 主动操控浏览器、本地应用、文件系统、执行命令 |
| **反思迭代（Reflection）** | 执行过程中自我检查，根据结果自动调整策略 |

这三项能力缺一不可：少了规划，只能做单步任务；少了工具调用，只能"动嘴"不能"动手"；少了反思，错了不会改。

---

## 三、L2-B 按运行环境细分

智能体"动手"的环境不同，能力边界和风险也完全不同：

| 运行环境 | 特点 | 代表产品 | 优势 / 风险 |
| :--- | :--- | :--- | :--- |
| **云端沙箱型** | 在云端隔离环境中执行代码 | Claude Code（部分功能）、Codex | ✅ 安全性高，误操作不影响本机；❌ 访问本地文件受限 |
| **本地终端型** | 直接运行在开发者本地机器，拥有完整的文件系统和命令行权限 | OpenCode、Cursor | ✅ 能直接改你的项目、跑你的命令；❌ 权限大，需谨慎授权 |

> 💡 **OpenCode** 是开源的 AI 编程代理，支持 75+ 模型，不锁定供应商，属于典型的本地终端型 L2-B。

---

## 四、L2-A 与 L2-B 的演进趋势

```
L2-A 被动响应  ──→  L2-B 目标驱动
   一问一答          自主规划 + 工具调用 + 反思迭代
   "帮我解释"        "帮我做完"
```

未来 L2-A 不会消失（轻量问答场景仍需要它），但高价值、多步骤的场景会越来越向 L2-B 迁移。

> 💡 **GitHub Copilot** 就是这条演进路径的活样本：从代码补全（L2-A）→ 聊天（L2-A）→ Agent Mode（L2-B），同一产品跨越了分类边界。

> 💡 **编程 AI 是 L2-B 中最活跃的子领域**，按运行形态可再分为 AI 原生 IDE / IDE 插件 / CLI 终端 / 云端 SWE Agent / 应用生成器五类，详见 [07 · 编程 AI 专项图谱](./07-coding-tools.md)。
