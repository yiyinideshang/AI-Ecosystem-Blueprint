# 03 · 混合角色产品（横跨多个层级）

> 现实中很少有"纯种"产品。多数玩家会组合 1~3 个层级，形成生态融合。本页给出一张"产品基因图谱"。

---

## 一、八种组合形态

| 组合类型 | 覆盖层级 | 典型产品 | 说明 |
| :--- | :--- | :--- | :--- |
| **纯 AI 模型** | L1 | ChatGPT 模型、DeepSeek 模型、GLM 模型、Qwen 模型、Agnes 模型 | **仅表示模型 API**。不直接提供终端用户界面，作为"大脑"供下游调用。 |
| **纯网关** | L3 | **OpenRouter、ZenMux** | **仅做聚合路由**。不自研模型，不开发终端应用。 |
| **非官方聚合应用** | L2-A | **Chatbox** | **封装调用**第三方模型。仅提供基础对话界面，不具备自主规划和工具调用能力。 |
| **模型 + 官方传统应用** | L1 + L2-A | **ChatGPT App**（OpenAI）、**DeepSeek App**（深度求索）、**智谱清言**（智谱 AI）、**Kimi App**（月之暗面） | **当前 C 端主流形态**。拥有自研模型，并由同一家公司开发官方应用，开箱即用。 |
| **模型 + 官方智能体** | L1 + L2-B | **Claude Code**（Anthropic）、**Codex** | **封装调用**自家模型，具备自主规划与执行能力。通常用于特定专业场景（如编程）。 |
| **第三方智能体应用** | L2-B | **OpenCode**、**Cursor**、**OpenClaw**、**Trae** | **封装调用**第三方模型。具备自主规划与执行能力。如 OpenCode 开源且模型无关，支持 75+ 模型。 |
| **智能体管理网关** | L3 + L2-B | **CCSwitch** | **AI 编程工具的"配置网关"**。不自研模型，但深度管理 L2-B 工具（如 Claude Code）的 API 配置，提供一键切换、故障转移、用量统计等调度能力。 |
| **全栈型平台** | L1 + L2 + L3 | **Agnes AI** | **生态闭环**。自研全模态模型（L1）+ 一体化办公 / 开发平台（L2）+ 开放 API 网关（L3）。 |

---

## 二、为什么会出现混合形态？

1. **锁定用户**：L1 厂商自建 L2 应用，让用户留在自己的生态里（如 ChatGPT App）。
2. **掌控体验**：L1 + L2-B 组合能深度调优模型与工具的配合（如 Claude Code）。
3. **降低门槛**：L2-B 应用接入多家 L1，避免被单一模型绑架（如 Cursor、OpenCode）。
4. **填充缝隙**：L3 管理网关解决"多智能体配置混乱"的痛点（如 CCSwitch）。
5. **生态野心**：全栈平台试图吃下整条链路（如 Agnes AI）。

---

## 三、如何一眼识别产品的"基因"？

看两个信号：
- **它卖什么**：卖 Token → L1；卖订阅 / 按任务计费 → L2；卖转发加价 / 会员 → L3。
- **它有没有自己的模型**：有自研模型 → 含 L1；纯转发不自研 → 含 L3。

详见 [05 · 商业模式与数据流向](./05-business.md)。

> 💡 编程 AI 领域有大量混合形态案例（GitHub Copilot、Cline、Devin、Windsurf 等），其中 GitHub Copilot 正从 L2-A 演进到 L2-B。完整图谱见 [07 · 编程 AI 专项图谱](./07-coding-tools.md)。
