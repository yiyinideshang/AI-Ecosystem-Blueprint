# 04 · 横向维度扩展分析

> L1 / L2 / L3 是纵向分层。本页补充几个横向切面，让认知更立体：模态、开源属性、网关演进方向。

---

## 一、L1 模型层维度

### 1. 按模态分

| 类型 | 说明 | 代表 |
| :--- | :--- | :--- |
| **纯文本模型** | 仅处理文本输入 / 输出 | DeepSeek-V4 |
| **多模态模型** | 支持图文等混合输入输出 | GLM-4.6（图文） |
| **全模态模型** | 支持文 / 图 / 视频的生成与理解 | Agnes-2.0 |

模态越全，应用场景越宽，但训练与推理成本也越高。

### 2. 按开源属性分

| 阵营 | 策略 | 代表 |
| :--- | :--- | :--- |
| **闭源派** | 仅开放 API 调用，权重不公开 | Claude 系列、Gemini 系列、Agnes 系列 |
| **开源派** | 提供权重下载，推动社区生态 | Qwen 系列、DeepSeek 系列 |

> 开源 vs 闭源不是对错题：闭源掌控体验与商业回报，开源换取生态渗透与社区贡献。两条路都在推动行业向前。

---

## 二、L3 网关层演进

L3 正从"单纯转发"走向"智能调度"，三个演进方向：

| 演进方向 | 定位 | 代表 | 核心价值 |
| :--- | :--- | :--- | :--- |
| **基础聚合** | 提供统一接口，多模型选择 | OpenRouter | 一个 Key 调多家模型，降低接入成本 |
| **质量保障** | 引入保险赔付、幻觉检测 | ZenMux | 为调用质量兜底，适合企业级场景 |
| **配置调度** | 专注 AI 编程工具的配置热切换、故障转移、本地代理路由 | CCSwitch | 解决多智能体配置混乱，一键切换 / 用量统计 |

---

## 三、一张图看横向切面

```
            闭源 ──┐
 L1 模型 ──────────┤ 按开源属性
            开源 ──┘
            纯文本 / 多模态 / 全模态  ── 按模态

 L3 网关 ── 基础聚合 → 质量保障 → 配置调度  ── 按能力深度
```

横向维度 + 纵向分层，共同构成给 AI 产品"定位"的坐标系。
